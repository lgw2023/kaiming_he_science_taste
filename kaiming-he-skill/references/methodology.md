# 何恺明的科研方法论（优化视角）

> **口径**：下面这套"把做科研看成优化问题"的框架，源自谢赛宁 2026 年七小时访谈中对何恺明工作方式的观察，以及涌现（JigmeDorje）《如何训练你的 Research Taste》一文的提炼。它是**对何恺明方法论的解读**，不是何恺明本人提出的理论。文中标注了哪些是何恺明本人的话、哪些是谢赛宁的转述/概括。原始出处见 `sources.md`。

把"做科研"想象成一个高维空间里的优化问题。那么决定你最终收敛到哪里的，不是你多努力，而是三件事：**你的 Loss Function 定义成了什么、你的 gradient 是不是真实的、你愿不愿意持续迭代。**

---

## 一、定义正确的 Loss Function

### 大多数人优化的是错的目标

学术界的激励结构默认让你优化：论文数、影响因子、H 指数、名望、奖项、物质奖励。在这套目标下做梯度下降，你的 gradient 会指向非常具体的方向：追当下最热的话题、在弱 baseline 上刷涨点、避开重要但短期出不了论文的方向。每一步都"理性"，但你大概率收敛到：一堆增量式论文，每篇涨几个点，换个 benchmark 就不行。你会成为熟练的论文生产者，但做不出 ResNet 这样的研究。

**问题不在方法，在 Loss Function。** 这些"虚无的相"是你损失函数里不该有的正则项——它们不帮你收敛到更好的解，只把梯度拽向与"理解问题"无关的方向。

### 何恺明的 Loss Function：理解问题本身

谢赛宁的概括：**何恺明的 Loss Function 不是"发表论文"，而是理解问题本身。**

同样的输入，会产生完全不同的 gradient：
- 在"发论文"的 loss 下，看到热门方向 → 梯度说：赶紧跟进，先占坑。
- 在"理解问题"的 loss 下，看到同一方向 → 梯度指向：它**为什么** work？底层假设是什么？这些假设在**什么条件下会 break**？

追问后者，才是最快逼近问题真实结构的路径。

> 谢赛宁："过分追求虚无的相（论文接收、得奖、名声、一时的称赞、物质奖励）是 research taste 不够好的原因。"

### 极致专注是正确 Loss 的副产物

谢赛宁描述何恺明的工作状态："他每天除了这一个问题之外，不会想任何其他的东西……他大部分的 mental cycle 都会被 allocate 到这一个具体的问题上。"

这不是因为他天生更能专注，而是因为 Loss Function 定义得足够清晰——每个 mental cycle 都有明确去处，正确的目标排除了名利杂讯对大脑带宽的消耗。

**怎么用**：用户描述研究困境时，先帮他识别真正在优化的目标。如果梯度被"发论文/追热点/刷点/赶 deadline 凑数"拽偏，明确指出来，并把目标拨回"理解这个问题"。这一步往往比任何技术建议都重要。

## 二、获取真实的 Gradient（科研就是 SGD）

Loss 定对之后，很多看似反直觉的行为就变得自然了。谢赛宁把何恺明的做法概括成 stochastic gradient descent：每一次实验、阅读、讨论，都是在高维损失地形上的一步随机采样，带回来的反馈信号才是 idea 的真正来源。

### 1. idea 是试出来的，不是想出来的

何恺明对谢赛宁说过：如果你坐在那儿凭空想出来一个 idea，它大概率不是好的——要么全世界一万个聪明人在想同一件事（你拼不过手速），要么这是个烂 idea 别人早试过了（无效）。

坐在屋里想，本质上是"零数据推断"。你对问题的理解只能通过与问题的交互获得：写代码、跑实验、复现别人的工作、在 baseline 上折腾。这些交互产生的"反常信号"或"逻辑冲突"，才是 idea 的来源。

**怎么用**：用户抛出一个纯靠想的 idea 时，不要先评判 idea 本身，而是引导他设计一个最小实验或复现，去和问题碰撞，让信号告诉他下一步。

### 2. 先把 baseline 做到天花板

何恺明的习惯：在开始"做研究"之前，先把 baseline 做到高得不能再高——不是堆 trick，而是把最基本的东西做到极致。

在弱 baseline 上的任何提升都是幻觉，甚至是误导。把 baseline 做到极致的过程，本身就是理解问题的过程：你会发现哪些因素真正重要、哪些改动的影响出乎意料、哪些所谓的 insight 其实只是弱 baseline 带来的假象。

> 谢赛宁："weaker baseline 上的提升可能是误导，没有意义，这是 research 的脚手架，不稳什么也做不出来。"

**怎么用**：用户拿弱 baseline 上的涨点当成果时，提醒他先把基线做到顶，并解释为什么否则结论不可信。

### 3. Spreadsheet 是梯度的测量仪器

谢赛宁说进 FAIR 的"第一课"是学会搭 research 表格——怎么设计行和列、包含哪些信息、怎么从结果推导结论。何恺明要求**每个实验之前先预测结果**，然后对比预测与实际的差异。

每一格数据都是一个 data point，告诉你当前点上 loss landscape 的局部形状。**预测与实际的"残差"（error signal），就是指引下一步迭代的真实梯度。**

**怎么用**：帮用户把实验组织成结构化的表格，并养成"先预测再跑"的习惯；重点不是那一格数字，而是预测错在哪——那里才有信息。

### 4. 负面结果也是 gradient

多数人讨厌负面结果（在"发论文"的 loss 下确实如此）。但在"理解问题"的 loss 下：
- 涨了 → 找到正向梯度
- 跌了 → 反方向可能有新洞察
- **没变化 → 零梯度，最没信息量**

前提是实验对照设计正确、变量干净。

## 三、Research Taste 是收敛的产物

到这里有个自然的问题：这些方法人人都能做，为什么是何恺明做出了 ResNet？

谢赛宁给的答案比"天赋"更有解释力：**Research Taste 不是某种神秘的"直觉"或天生的"眼光准"，而是在正确的 Loss Function 上做了足够多次梯度下降之后的参数收敛状态。**

当你持续、诚实地追问"这个问题的本质是什么"，你对问题的内部表征会越来越接近它的真实结构。到某个临界点，别人看到的是一堆分散的论文和方法，你看到的是它们背后共享的数学结构。

### 高维抽象：透视共通本质

谢赛宁说何恺明的能力在于"能够把深度学习里的模块抽象成数学公式""在高维度的抽象空间中建立联系"。两个例子：

- **ResNeXt 与 MoE 的相通**：ResNeXt（2016，**一作谢赛宁**，何恺明等）用分组卷积把网络通道拆成多组并行。**多年之后，谢赛宁回顾时才意识到**——当年的 grouped convolution，本质上和如今大模型里的 MoE（Mixture of Experts）是相通的。这是谢赛宁**事后**的洞察，不是何恺明当年的预见；它体现的是何恺明反复示范的那种能力：把模块抽象成数学、在高维空间建立联系。
- **超前预判 scaling**：在 2018、2019 年前后（远早于 Scaling Law 成为行业共识），何恺明就对谢赛宁说"我们一定需要把模型变得更大，把数据变得更大"。

> ⚠️ 归因纪律：第一条务必写成"谢赛宁事后回顾"，且 ResNeXt 一作是谢赛宁。不要写成"何恺明当年提出 ResNeXt 时就意识到它等于 MoE"——那是常见的归因漂移。也不要把技术相通拔高成"完全相同的数学结构"。

### Taste 是可以训练的

这是整个框架最振奋人心的推论：既然 taste 是 SGD 的收敛产物，它就不是天才的专利。条件只有一个——**你的 Loss Function 得定义对**。

何恺明从 MSRA 到 FAIR，从 ResNet 到 MoCo 到 MAE，每一步都在做同一件事：理解视觉表征的本质。他用了十几年、几十篇论文、无数次实验做这个梯度下降。ResNet 不是从天上掉下来的，是这个优化过程走到某一步时，解空间里自然出现的一个点。

## 四、SGD 的节奏：六个月黄金周期

谢赛宁给出的科研节奏：

- **前 1-2 个月：纯探索期。** 不要坐着空想——"你要真的像一个 hacker 一样去 play with，去玩一些东西"。复现 baseline、在别人工作上做拓展、推公式、写代码。目标不是产出，是找到微弱的 signal。
- **中间 2-3 个月：集中收敛期。** 围绕找到的 signal 饱和攻击，做完整、详尽的对照与消融实验，完善方法。
- **最后 1 个月：极致打磨期。** 何恺明的习惯是 deadline 前一个月就写完初稿，剩下时间反复逐句推敲——**"写不清楚，往往意味着你还没完全理解。"**

但比节奏更重要的是谢赛宁这句：

> "对 research 最重要的事情不是从 A 点通到 B 点（A 是 idea，B 是 paper），而是这个过程中你到底能找到什么样的 signal，你的 gradient 到底在哪。"

每个人起点不同、路径不同、感知到的 gradient 不同，所以收敛到的 idea 不同——这就是为什么好的 research 有强烈的个人风格。它不是被某个统一方法论批量生产出来的。

## 五、真诚交流是最高效的梯度共享

> 谢赛宁："在这个世界上，只有人与人之间真诚的交流是重要的，也许其他都不重要。"

在这个框架里这句话有精确含义：**真诚的交流是最高效的 gradient signal 共享。** 当一个 Loss Function 定义对了的人，把他在优化路径上积累的理解无保留地传给另一个人，等价于直接传递了 gradient——把几十步 SGD 的参数解直接灌给对方。

这也解释了何恺明为什么能带出一大批顶尖研究者：
- **张祥雨**（ResNet 团队、最年轻未来科学大奖得主）："我的两位导师，尤其是我的 mentor 何恺明和我在 MSRA 的指导老师孙剑，让我们始终坚持简单和本质的原则。"
- **胡瀚**（Swin Transformer，ICCV 2021 最佳论文）："正是因为有着孙剑、何恺明等在科研品味和科研素质方面的培养和训练……"
- **谢赛宁**（DiT 共同提出者）：七小时访谈中，何恺明是被提及最多的名字。

**怎么用**：鼓励用户去和真正懂问题的人深度交流，而不是闭门造车；好的对话能直接传递梯度，省下大量自己摸索的 SGD 步数。

> **"应无所住而生其心。确保你的 Loss Function 定义对了，然后在你自己的路径上，诚实地做梯度下降。"**
